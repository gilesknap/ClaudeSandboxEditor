# MD Collaborative Editor

Local GitHub-style markdown editor shared between the user (browser) and Claude (terminal). See README.md.

- Package layout: code in `src/md_collab_editor/` (`server.py`, `static/`), installed as the `md-editor` command via `pyproject.toml` (hatchling, no dependencies). `docs/` is just a sample folder, not packaged. MIT licensed; PyPI name `md-collab-editor`. The version lives only in `src/md_collab_editor/__init__.py` (`__version__`); to release, bump it, commit, then push a matching tag (`git tag v0.1.1 && git push origin v0.1.1`); `.github/workflows/publish.yml` builds and publishes via PyPI trusted publishing and fails if the tag and `__version__` differ. PyPI never accepts a version twice.
- Run: `uv run md-editor [folder-or-file]` (or `md-editor` once installed with `uv tool install`), serves http://127.0.0.1:8765. Default document root is the current folder; the user can switch the root at runtime with the in-app file browser (`/api/root`), so check the status bar or `/api/config` for the folder currently open.
- **Collaborating on a document:** edit the `.md` file on disk directly with Edit/Write. The open editor reloads it live and flashes the change, so there is no need to go through the browser. Avoid rewriting the whole file while the user is typing; prefer targeted edits.
- Ask Claude: `ask_claude` in `server.py` runs `claude -p` (tools Skill and Read, `SYSTEM_PROMPT`). `--ask-agent` (default `uvx claude-sandbox@latest`, else `$MDEDIT_ASK_AGENT`; `none` turns it off): an argv whose basename is `claude` runs natively on pipes in `native_ask_dir()` (`$XDG_CACHE_HOME`, else `~/.cache`, `/md-editor/ask`, mode 0700, refused unless the user's own); anything else is a launcher, run as `<launcher> shell -c SCRIPT` (with `CLAUDE_SANDBOX_SHELL=sh`, else claude-sandbox runs SCRIPT in the user's own shell) on a PTY in ROOT, with the prompt in a 0600 `ROOT/.md-editor-ask-<hex>.txt` that SCRIPT passes to `claude` as an argument, run in the container's `~/.cache/md-editor/ask`, which claude-sandbox's wrapper always binds (the container's `claude` is that script(1) wrapper, so `-p` gets a TTY stdin and won't read it; hence ~100 kB max, see `ASK_ARG_MAX`). Base sessions (`ASK_BASES`, made early by `/api/ask/prepare`) hold each document version; cards fork one (`--resume --fork-session`) with a `<request>` (plus a `<document_update>` diff after small edits), Retry/Refine fork the card's returned `session`, and a failed fork falls back to one stateless call; the parent session is forgotten only when claude says it is gone (`SESSION_MISSING`, "No conversation found with session ID:"). `end_asks` ends launcher calls still running (and deletes their prompt files) when md-editor exits.
- Side-panel terminal: `TermSession` in `server.py` runs the `--agent` command (default `uvx claude-sandbox@latest`, else `$MDEDIT_AGENT`; `none` turns it off) on a PTY in ROOT. There is one shared session: it survives browser reloads (scrollback replay), doesn't follow `/api/root` changes, and its process group is killed when md-editor exits, or a second after the agent exits if something it started still holds the PTY quietly open. Both agents get `child_env()`, which drops the markers a parent Claude Code session sets (`CHILD_ENV_DROP`; `CLAUDE_CODE_CHILD_SESSION` would turn off the terminal's transcript). It's served by a hand-written RFC 6455 WebSocket at `/api/term` (stdlib only). Binary frames carry PTY bytes both ways; text JSON carries `resize`/`restart` from the client and `status` from the server. The server pings every 30 s (`MDEDIT_WS_PING`) and drops a client that has sent nothing since the last ping. On connect a running or exited session always sends one replay frame (possibly empty) after the first status: term.js relies on that to keep xterm's answers to replayed terminal queries out of the PTY. The front end is `static/term.js` (app.js only wires it up).
- Workspace/IDE API in `server.py` (the "workspace" and "git" sections; JSON, errors `{"error"}` via `Handler.answer` and `ApiError`, routed by `GET_API`/`POST_API`): `/api/tree`, `/api/stat` (polled), `/api/file` (kinds text/binary/image/too_large; text always LF, and PUT puts CRLF back and keeps the file mode), `/api/new` (`exact` skips the `.md` suffix), `/api/rename`, `/api/delete` (`dry_run` counts), `/api/allfiles`, `/api/search` (git grep or a walk; `col`/`len`/`offset` in UTF-16 units), `/api/git/{info,status,show,discard}`. Paths are ROOT-relative; `safe_path(rel, follow=False)` keeps a symlink itself for new/rename/delete. git runs via `git()` with `GIT_OPTS` (overrides colour, quotePath, diff.relative, grep.fullName, and switches off what a repo's config could make git run on the host, since the sandboxed agent can write `.git`: `core.fsmonitor=false`, `core.hooksPath=/dev/null`, `submodule.recurse=false`; for `FILTER_CMDS` (status, diff, restore, checkout, rm) `filter_opts` blanks every clean/smudge/process filter driver except Git LFS's exact commands), `GIT_OPTIONAL_LOCKS=0` (status polling must not take index.lock while Claude commits) and literal pathspecs for user paths, except `check-ignore`, which refuses them (paths get a `./` prefix instead). `git_repo()` caches the work tree per ROOT for 3 s; a ROOT that git ignores is treated as no repo for tree/allfiles/search. `git_ignored` asks `check-ignore --no-index` first (with the index it costs paths × index size), then the index for ≤ 64 candidates or `ls-files` of the folder; `api_tree` asks about a symlinked folder's real path (git refuses paths beyond a symlink). Folder stamps (`dir_stamp`) hash names and types only (plus a `.gitignore`'s mtime), so saving a file doesn't relist its folder. Status drops nested repos/worktrees (`dir/` entries) and counts them as `nested`. Searches stop after `SEARCH_TIMEOUT` (504; `MDEDIT_SEARCH_TIMEOUT` shortens it) or when the client disconnects (`Watchdog`, `REQUEST.conn`; search.js aborts a superseded search); a regex search runs in a child process (`search_child`: `python -I -c` importing this module, killed by process group) because Python's re can backtrack for hours holding the GIL. The git engine greps tracked files, then untracked non-ignored ones as literal pathspecs (`--untracked` would drop tracked files that match an ignore rule), skips files over 5 MB, and `grep_records` parses in one pass with lines capped at `LINE_MAX`. The walk reads regular files only (`lstat`: a FIFO would block it for ever). `safe_path` turns a symlink loop into ValueError (3.9-3.12 raise RuntimeError; 3.13 hands back the link). Query strings and `/raw/` paths decode with `surrogateescape`, and the front end encodes paths with `UI.encPath`, so non-UTF-8 file names round-trip. `Handler.answer` has a catch-all 500. Tests: `tests/test_fs.py`, `test_git.py`, `test_search.py` (both engines), helpers in `tests/gitutil.py`.
- Every request passes `Handler.guard` first, else 403: Host must be 127.0.0.1, localhost or [::1] (any port, so port forwarding works), and Origin, required on PUT/POST and the WebSocket, must be `http://` + Host. `/api/` and `/raw/` also refuse `Sec-Fetch-Site: cross-site`/`same-site` (another site's `<img>` or `<iframe>`). Test clients must send a matching Origin.
- Tests: `uv run pytest` (`tests/`, dev group in `pyproject.toml`; CI in `.github/workflows/test.yml` on 3.9 and 3.13). Each test starts real servers (`python -m md_collab_editor --port 0`, see `conftest.py`/`helpers.py`) and fails if any process they started outlives them. `tests/fakes/fake-sandbox` stands in for `uvx claude-sandbox@latest` and `tests/fakes/claude` for `claude -p` (flag files in `$FAKE_CLAUDE_STATE` make it fail or hang); `MDEDIT_ASK_TIMEOUT` shortens the 600 s Ask timeout. Tests that need Linux tools (util-linux `script`, GNU `stat`, `/proc`) are marked `needs_linux` (`helpers.py`) and skip elsewhere. `test_e2e.py` drives the page with Python Playwright (3.10+, needs `uv run playwright install chromium` and CDN access), skipping without a browser unless `MD_EDITOR_E2E=require` (set in CI).
- Front end: no build step; libraries come from CDNs (marked 12, CodeMirror 5 with its merge addon and `diff_match_patch`, DOMPurify, highlight.js, KaTeX, mermaid 10, github-markdown-css, Typo.js, xterm.js 5 with addon-fit and addon-web-links).
- Front-end modules (plain scripts exposing globals, loaded in this order before app.js; each documents its interface at the top): `ui.js` (`UI`: api, store, event bus `root`/`ready`/`theme`, `UI.menu` context menus, `UI.dialog`/`confirm`, `UI.toast`, `UI.statusItem` status-bar slots, `UI.stat` the one shared `POST /api/stat` poll, `UI.sendToTerminal`), `activity.js` (`Activity.register(id, {icon, title, panelEl, onShow, onHide})` → handle with `panel`, `setBadge`; Source Control and Search start as empty placeholders), `tabs.js` (`Tabs`: one model per open file = a `CodeMirror.Doc` swapped into app.js's single editor with `swapDoc`; preview/pinned tabs, custom tabs via `Tabs.openCustom` + `Tabs.registerType` for persistence, `Tabs.acquire`/`linkedDoc` for a second editor on a file, events `activate`/`change`/`saved`/`disk-change`/`dispose`…; tabs remembered per root in `mdedit.tabs:<root>`), `explorer.js` (`Explorer`: lazy tree, `decorate` hook), then app.js (`cur` = the active file tab's model; cards hold `c.model` and mark its Doc; `window.App.showTerminal`). Autosave is per category (`mdedit.autosave.md` default on, `.other` off); dirty = `!doc.isClean(cleanGen)`. A model deleted on disk (`markDeleted`, also on a 409 whose version is "0") is never autosaved (`save(m, force, auto)`), and closing it asks; undoing back to clean after a conflict re-checks the disk. `Tabs.renameBlocked` stops Explorer renaming onto an open dirty deleted file; `renamePath` closes clean tabs at the destination. Activity keeps the remembered panel id until it is registered (`shown()`) and calls a re-registered panel's real `onShow` in a microtask. The side bar and Claude panel widths are clamped so the editor keeps 240 px (`maxWidth`, `fitColumns`). CodeMirror modes autoload via `mode/meta` + `addon/mode/loadmode` (simple/multiplex addons are preloaded for the modes that need them).
- `scm.js` (`SCM`, after explorer.js): the Source Control panel polls `/api/git/info` + `/api/git/status?base=head|branch` (2 s while open, 10 s otherwise, and right after saves; base in `mdedit.scm.base`), sets the badge and the `#stat-branch` status item, and shows letters in the Explorer through `Explorer.decorate` (calling `Explorer.render()` only when they change). Diff tabs are `Tabs.openCustom` tabs of kind `diff` (id `scm:<mode>:<path>`, restored through `Tabs.registerType`) that hold the file's model. The side-by-side view is `CodeMirror.MergeView` (`connect: 'align'`, `revertButtons`; `diff_match_patch` must load before `merge.min.js`) with `value: Tabs.linkedDoc(model)`, so its right side shares the file's history and dirty state. It is only built while its tab is on screen (CodeMirror measures what it shows); on show it refreshes and forces the addon's realign (`mv.left.forceUpdate('full')`). Rebuilding one must first `swapDoc` the linked doc out of the old editor. The inline view is a read-only CodeMirror of interleaved rows, rebuilt 300 ms after model changes. Gutter change bars are `addLineClass(line, 'gutter', 'scm-add|scm-mod|scm-del')` on each model's Doc (so they follow `swapDoc`), drawn by CSS on `.CodeMirror-gutter-background` in an 8 px `scm-gutter` column. `lineChunks` (`linediff.js`) uses dmp's `diff_linesToChars_` with `\n` appended to both sides, so chunk lines are CodeMirror lines; it is 16-bit, so over 65,000 distinct lines fall back to one coarse chunk. The gutter's diff runs in `scm-worker.js` (one at a time, skipped when the doc's `changeGeneration()` and the base are unchanged; synchronous fallback if the worker fails); a diff tab caches its chunks by generation (`diffChunks`), skips stats while hidden, and parks a hidden MergeView's editor on an empty Doc (the addon re-diffs on every change and on `swapDoc`). Inline revert arrows and the menu's Revert check that the generation is the one the rows were built from. HEAD text is cached per path until `info.head` changes. Discard uses `Tabs.reload(model)` to drop unsaved edits. Alt/Shift+Alt+F5 is a `document` listener. Tests: `tests/test_e2e_scm.py`.
- `search.js` (`Search`, after explorer.js/scm.js): quick open (Ctrl/Cmd+P, a modal over `/api/allfiles` with its own DP fuzzy matcher; recent files per root in `mdedit.recent:<root>`, fed by Tabs `activate`), the Search panel (`/api/search`, one request in flight, 300 ms debounce; query/options/globs in `mdedit.search`), and Send to Claude terminal for any CodeMirror whose doc is a model's or linked to it (`Search.fileOf`): Ctrl/Cmd+Alt+L and the editor context menu are `document` listeners that skip events already `defaultPrevented` (app.js's extraKeys, the spelling menu, scm.js's diff menus), and Shift+right-click keeps the browser's menu. Ctrl/Cmd+P and Ctrl/Cmd+Shift+F are caught on `window` in the capture phase (CodeMirror binds Shift-Ctrl-F to replace, so replace moves to Ctrl-H in `keyMap.pcDefault`) and skipped in `#term`, dialogs and the folder browser. `UI.sendToTerminal` is async: it waits up to 5 s for a terminal that is still connecting (`Term.running()`: this connection's status says running, so `Term.cwd()` is known), and `Term.sendText` goes through term.js's input queue (`pending`/`flush`), so text sent while the replay is drawn waits behind typed keys. Chrome logs every 4xx fetch as a console error, so e2e tests that expect a 400 (invalid regex) must drop that entry. Tests: `tests/test_e2e_search.py` (the terminal test runs `bash --norc --noprofile -i` with `HISTFILE=/dev/null` and reads the bracketed paste from the WebSocket frames).
- Gotchas: DOMPurify strips attributes containing `-->` (so mermaid source is kept as element text); mermaid.render is not re-entrant (renders are queued); blur CodeMirror before calling setSelection from preview code, or its input poll re-types the selection and wipes markers. Spell checking is our own (`static/spell.js`: Typo.js plus the `dictionary-en-gb` Hunspell files from jsDelivr, suggestions in `spell-worker.js`), shown by a CodeMirror overlay; code/URL/HTML exclusions are added per line in app.js's `renderLine` handler. A model's Doc must only ever be attached to the main editor (a Doc can't be in two editors): other editors use `Tabs.linkedDoc(model)` (shared history, so one dirty state) and unlink it when done. The tree re-renders only on structure changes (`updateMarks` otherwise), so a click's rows aren't replaced between mousedown and click. Explorer gets a folder's stamp *before* its listing, so a change in between only causes one extra reload. tabs.js's `renderStrip` keeps the tab elements: Chrome only fires dblclick (pin) when both clicks land on the same node. Horizontal padding must go on `pre.CodeMirror-line`, never on `.CodeMirror-lines`, which shifts the per-line gutter elements (line numbers, change bars) off their columns. `location.hash` names the active tab's file (set in `Tabs.activate`; empty for a diff): app.js reads it *before* `Tabs.restore()`, which rewrites it, and opens it afterwards, and opens the command line's file (`conf.initial`) once per browser tab (sessionStorage), so a reload keeps the tab that was on screen. Editing pins the active preview tab only; a preview tab is replaced unless it is the last holder of a dirty model (`losesWork`), and a new Ask Claude card pins its file's preview tab (closing the tab cancels its cards). In a window ≤ 800 px wide (the CSS breakpoint) the side bar and the Claude panel are overlays, one at a time: `Activity.setSidebar(true)` hides the panel and app.js's `showClaudePanel()` hides the side bar without remembering that. Alt+W (close tab) is a `document` listener that leaves text boxes alone. `e2e` tests for these are in `tests/test_e2e_ide.py`.
