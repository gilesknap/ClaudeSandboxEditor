# MD Collaborative Editor

Local GitHub-style markdown editor shared between the user (browser) and Claude (terminal). See README.md.

- Package layout: code in `src/md_collab_editor/` (`server.py`, `static/`), installed as the `md-editor` command via `pyproject.toml` (hatchling, no dependencies). `docs/` is just a sample folder, not packaged. MIT licensed; PyPI name `md-collab-editor`. The version lives only in `src/md_collab_editor/__init__.py` (`__version__`); to release, bump it, commit, then push a matching tag (`git tag v0.1.1 && git push origin v0.1.1`); `.github/workflows/publish.yml` builds and publishes via PyPI trusted publishing and fails if the tag and `__version__` differ. PyPI never accepts a version twice.
- Run: `uv run md-editor [folder-or-file]` (or `md-editor` once installed with `uv tool install`), serves http://127.0.0.1:8765. Default document root is the current folder; the user can switch the root at runtime with the in-app file browser (`/api/root`), so check the status bar or `/api/config` for the folder currently open.
- **Collaborating on a document:** edit the `.md` file on disk directly with Edit/Write. The open editor reloads it live and flashes the change, so there is no need to go through the browser. Avoid rewriting the whole file while the user is typing; prefer targeted edits.
- Side-panel terminal: `TermSession` in `server.py` runs the `--agent` command (default `uvx claude-sandbox@latest`, else `$MDEDIT_AGENT`; `none` turns it off) on a PTY in ROOT. There is one shared session: it survives browser reloads (scrollback replay), doesn't follow `/api/root` changes, and its process group is killed when md-editor exits, or a second after the agent exits if something it started still holds the PTY quietly open. The agent gets `child_env()`, which drops the markers a parent Claude Code session sets (`CHILD_ENV_DROP`; `CLAUDE_CODE_CHILD_SESSION` would turn off the terminal's transcript) and an IDE's `CLAUDE_CODE_SSE_PORT`. It's served by a hand-written RFC 6455 WebSocket at `/api/term` (stdlib only). Binary frames carry PTY bytes both ways; text JSON carries `resize`/`restart` from the client and `status` from the server (and the IDE link's messages, below). The server pings every 30 s (`MDEDIT_WS_PING`) and drops a client that has sent nothing since the last ping. On connect a running or exited session always sends one replay frame (possibly empty) after the first status: term.js relies on that to keep xterm's answers to replayed terminal queries out of the PTY. The front end is `static/term.js` (app.js only wires it up).
- IDE link: md-editor is the terminal session's IDE, as VS Code is with Claude Code's extension, speaking Claude Code's IDE protocol (MCP, JSON-RPC 2.0, one message per WebSocket text frame) — the "ide link" section of `server.py`, `term.js` and `proposal.js`. No MCP message can submit a prompt, so an ask is typed into the PTY.
  - `IdeBridge`: one per spawned agent (`TermSession._spawn_locked`; shares the session's lock; closed on exit, Restart and kill), unless `--ide-link off` / `MDEDIT_IDE_LINK=off`. It holds a 32-byte token, the listener, the lock file `<port>.lock`, the waiting `openDiff`s (`diffs`, keyed by string ids `<DIFF_SALT>-<n>`: the salt is per process, so a page that outlives an md-editor and reconnects to the next never takes a new proposal for an old one) and `state` off | waiting | connected, which the terminal status carries as `ide` (+ `ide_reason`, `diffs`).
  - Listener: `IdeTCPServer`/`IdeUnixServer` + `IdeHandler`, never `Handler` (no `/api/*`): only a WebSocket upgrade on `/` with `X-Claude-Code-Ide-Authorization` (`hmac.compare_digest`; no Origin/Host check, the token is the gate and a browser cannot send it), `Sec-WebSocket-Protocol: mcp` echoed, permessage-deflate refused, 16 MiB messages. Frames are read by `WSReader`, shared with `/api/term`. The newest connection replaces an older one (Claude's `/ide` reconnects). Anything in the jail can reach the socket, so `IdeServer` serves at most `IDE_CONNS_MAX` connections at once (more are closed at once) and `IdeHandler.timeout` gives each `IDE_HANDSHAKE` s (`MDEDIT_IDE_HANDSHAKE`) to send its upgrade, lifted after the 101.
  - Native transport (argv[0]'s basename is `claude`): TCP on 127.0.0.1, `CLAUDE_CODE_SSE_PORT` in the agent's environment, lock in `${CLAUDE_CONFIG_DIR:-~/.claude}/ide` with md-editor's pid.
  - Launcher transport (a `claude-sandbox`/`claude-container` word in the agent command; `ide_mode` returns None, so no link, for any other agent unless `--ide-link native|launcher` forces a mode): Unix socket `<session cwd>/.md-editor-ide-<P>.sock` (0600; a path over 107 bytes → no link), lock in the jail's `~/.claude/ide` = `${CLAUDE_SANDBOX_SHARED_CONFIG:-~/.config/terminal-config}/.claude/ide` (no link unless that `.claude` exists) with `"pid": 1` (alive in the jail's pid namespace, so Claude's stale-lock sweep keeps it), and `--settings` appended to the agent's argv: `env.CLAUDE_CODE_SSE_PORT` plus a SessionStart hook running `setsid socat TCP4-LISTEN:P,bind=127.0.0.1,reuseaddr,fork UNIX-CONNECT:<sock>` in the jail. Every non-`claude` agent gets these arguments, so `--agent bash` needs `--ide-link off`.
  - Lock files: 0600, written whole by `write_lock` in a folder opened without following symlinks (`open_lock_dir`: in launcher mode the agent can write it), read without blocking (`read_lock`). Each carries `mdEditorHostPid`: `sweep_ide_locks` deletes dead md-editors' locks and sockets at start (but leaves a lock whose socket still answers, `socket_alive`: in launcher mode any sandboxed agent can write a lock naming another project's live socket; each lock is checked by `_sweep_lock` under a catch-all, and `pid_alive` takes a pid os.kill cannot hold (OverflowError) for a dead one, so no lock can stop md-editor starting; `read_lock` and the link's message parser also catch RecursionError, JSON nested too deep), `check_lock` rewrites a deleted lock every 5 s, and close deletes it only if it still holds our token. `ide_socket` hides the sockets from the tree, folder stamps, quick open, search and Source Control.
  - MCP from Claude: `initialize` → `IDE_INSTRUCTIONS` (the lasting parts of the old Ask prompt: markdown structure, British English); `tools/list` → openDiff, close_tab, closeAllDiffTabs, getDiagnostics (NEVER executeCode: the model would see it); `getDiagnostics` → `[]`; `ping` → `{}`; anything else → -32601, logged. `openDiff` for a text file inside the session's folder (real path; not `.git`; the proposal ≤ `IDE_DIFF_MAX` = 3 MiB as JSON (`json_size`), so the page's Accept, the whole edited file in one `/api/term` message, fits under `WS_MAX_MESSAGE` = 4 MiB, and proposal.js refuses an Accept the user grew past it (`ANSWER_MAX`); read by `read_inside`, one name at a time from the folder with `O_NOFOLLOW`, so a symlink swapped in after the check is refused) goes to every browser as `diff` (again on attach) and the first `diff-decision` answers it: Accept → `FILE_SAVED` + the contents (md-editor never writes the file, Claude does; the editor's LF text goes back with the *proposal's* line ends: Claude 2.1.280 reads a CRLF file as LF, proposes LF, diffs the answer against that and writes the CRLFs back itself, so CRLFs would make every line a change), Reject → `DIFF_REJECTED` + the tab name. Any other path gets an `isError` result, so Claude asks in the terminal only. `close_tab`/`closeAllDiffTabs` answer waiting ones `TAB_CLOSED`; the session's end answers them `DIFF_REJECTED`.
  - Browser → server (text JSON on `/api/term`): `selection {path (ROOT-relative), start, end ({line, character}, 0-based, UTF-16), text}` → `selection_changed` only for a file inside the session's folder, remembered and sent again on `ide_connected` (twice); anywhere else `clear_selection` (once) sends an empty range with no `filePath`, which clears Claude's (a null selection it would ignore, and attach the old one to the next prompt); `ask {text, path?, start?, end?}` → first `_wait_ready` (a session just started: Claude Code keeps text typed before its prompt is up but drops the Enter. For Claude Code (`ide_mode()` not None, even with the link off) only its prompt glyph will do (`_Proc.prompted`, set by `_read_loop` once `❯` appears): the ask waits at most `START_WAIT` s (`MDEDIT_START_WAIT`, 20) and then fails, typing nothing, since claude-sandbox is silent for long stretches while it makes its container. Any other agent: until its output has been quiet `START_QUIET` s (`MDEDIT_START_QUIET`), at most `START_WAIT` s after spawn. The page is told `waiting` after 1 s), then refused while a diff waits or a menu is on screen (`_answer_pending`, checked again before the Enter: the Enter would answer "1. Yes"; `prompt_state` reads the last `❯` Claude Code drew: followed by `N.` it marks a menu's choice, else its input box), then with the link `selection_changed`, an MCP `ping` whose answer is the barrier, 50 ms, the question as one bracketed paste and `\r` 0.1 s later; without it (or with no answer in 2 s) `@path#La-b question` and `\r`, typed; a whole-file ask (no range) starts `@path ` either way; an ask about a file outside the session's folder clears Claude's selection (and pings) first; `mention {path ('' = the folder), start?, end?}` → `at_mentioned`, else `@path#La-b ` typed (also for a path with whitespace: Claude Code inserts `at_mentioned` paths unquoted, and its parser stops at a space), never Enter; `diff-decision {id, accept, contents?}`. Server → browser: `status` (`ide`, `ide_reason`, `diffs`), `diff {id, path (ROOT-relative or null), file (absolute), title, old (disk, LF), new (LF), exists}`, `diff-close {id}`, `waiting {what, seq?}`, `sent {what, ok, via: ide | typed}` or `{ok: false, error}` (toast; `seq` echoed).
  - Front end: term.js joins `/api/term` at load even while the panel is hidden (no xterm then, output dropped, no resize so no session starts), so waiting proposals open and the selection is sent; `create()` closes that connection and opens one for the terminal's replay. `Term.select` (debounced 150 ms, 64 Ki characters; from app.js's `trackSelection` on `cursorActivity` and tab activation — a preview selection arrives as the editor selection it sets — and scm.js's `reportSel` for diff editors, in working-file lines; zero-width = just the file; re-sent on every connection, every new session id (a new bridge starts with none) and window focus), `Term.ask` (ask bar, pill, presets; app.js saves a dirty file first, with a toast; zero-width = the whole file, so no start/end), `Term.mention` (`UI.sendToTerminal`; lines {from, to} → start `{from-1, 0}`, end `{to, 0}`). Asks and mentions go through term.js's input queue, so they keep their place among typed keys; decisions made while disconnected wait in `outbox`. The header's `#term-ide` shows the state. `Proposals` (proposal.js): custom tab `claude-diff:<id>`, never persisted; MergeView with `origLeft` = the disk text and `value` = a NEW Doc, never the model's; Accept (Ctrl/Cmd+Enter; disabled while the right side equals the disk text), Reject (Ctrl/Cmd+Shift+Enter, or closing the tab); `diff-close` closes without answering, and so does `Proposals.sync(status.diffs)` (every status) for any id the server no longer waits on; an id already shown or answered is ignored when sent again (never re-activated). A proposal opens without being activated (and with a toast) when a key was pressed outside the terminal in the last 2 s and an editor or text box has focus. Its tab is `waiting` (a Tabs spec function): `Tabs.closeAll` (opening another folder) keeps such tabs and Close saved skips them; on the `root` event proposal.js moves each one's path and hold to the new folder. While one waits, `Tabs.hold(path)` makes the file's tab read-only (app.js's toolbar, task boxes and spelling fixes check `cm.isReadOnly()`), shows a banner and stops its saves, until Claude's write lands (at most 4 s after Accept); `Tabs.linkedDoc` docs refuse edits while their model is held (`beforeChange`), and scm.js makes its MergeView editor read-only on Tabs' `hold` event (so undo keys are suppressed rather than cancelled, which would wipe the shared history).
  - Gotchas: `selection_changed` must always carry a `selection` object (Claude ignores one without), and Claude only listens a moment after `ide_connected`. `TAB_CLOSED` that does not answer a `close_tab` is an ACCEPT of the proposal unchanged, so closing a diff tab must send `DIFF_REJECTED`; `FILE_SAVED` with the file's own text counts as a rejection. Claude sends `openDiff` only when it would ask permission (manual mode), never in auto or accept-edits mode. Text typed into the PTY loses control characters, ESC included (`paste_bytes`), so it cannot end the bracketed paste. Whatever a client sends (`pid`, file names) is printed with `!r`, never raw: the console is the host's terminal. `child_env` drops an inherited `CLAUDE_CODE_SSE_PORT` (VS Code's terminal sets it).
  - Tests: `tests/test_ide.py` (a fake agent, which draws Claude Code's prompt or a menu on request (`say`), and a client replaying the frames Claude Code 2.1.280 sends, in both transports, with the generated socat hook run for real) and `tests/test_e2e_session.py` (the page, a bash agent called `claude` that first draws Claude Code's `❯`, so asks need not wait, and `FakeIde`, Claude Code's end of the link).
- Workspace/IDE API in `server.py` (the "workspace" and "git" sections; JSON, errors `{"error"}` via `Handler.answer` and `ApiError`, routed by `GET_API`/`POST_API`): `/api/tree`, `/api/stat` (polled), `/api/file` (kinds text/binary/image/too_large; text always LF, and PUT puts CRLF back and keeps the file mode; PUT's 409 carries the disk's `text`, null once it is not text, when tabs.js only offers to overwrite), `/api/new` (`exact` skips the `.md` suffix), `/api/rename`, `/api/delete` (`dry_run` counts), `/api/allfiles`, `/api/search` (git grep or a walk; `col`/`len`/`offset` in UTF-16 units), `/api/git/{info,status,show,discard}`. Paths are ROOT-relative; `safe_path(rel, follow=False)` keeps a symlink itself for new/rename/delete. git runs via `git()` with `GIT_OPTS` (overrides colour, quotePath, diff.relative, grep.fullName, and switches off what a repo's config could make git run on the host, since the sandboxed agent can write `.git`: `core.fsmonitor=false`, `core.hooksPath=/dev/null`, `submodule.recurse=false`), `GIT_OPTIONAL_LOCKS=0` (status polling must not take index.lock while Claude commits), `GIT_LFS_SKIP_SMUDGE=1` (git-lfs never downloads, so runs no transfer agent, credential helper or ssh) and literal pathspecs for user paths, except `check-ignore`, which refuses them (paths get a `./` prefix instead). `FILTER_CMDS` (status, diff, restore, checkout, rm) run clean/smudge/diff drivers, so they must not read the agent-writable `.git/config` at command time (the old `-c`-blanking read it in a separate process — a TOCTOU the agent could win by swapping `.git/config`, SEC-GIT-001): `git()` instead builds a private `frozen_git_dir(cwd)` and runs `git --git-dir=<frozen> --work-tree=<top>` with `GIT_INDEX_FILE=<real index>`. The frozen dir shares objects (alternates) and the index with the real repo, pins HEAD to the current sha, and its `config` (`write_frozen_config`) holds ONLY the repo's `core`/`extensions`/`index` keys (minus command-valued core keys, `FROZEN_CORE_SKIP`) plus Git LFS's exact `filter.lfs.*` — dropped when any `lfs.extension.*`/`lfs.customtransfer.*`/`lfs.standalonetransferagent` key exists; every other driver, include and alias is left out. Because git reads only this agent-unwritable copy, a driver written into `.git/config` never runs however it is rewritten. Non-FILTER_CMDS (rev-parse, config, ls-files, cat-file, check-ignore, grep) run normally and don't execute drivers. `git_repo()` caches the work tree per ROOT for 3 s; a ROOT that git ignores is treated as no repo for tree/allfiles/search. `git_ignored` asks `check-ignore --no-index` first (with the index it costs paths × index size), then the index for ≤ 64 candidates or `ls-files` of the folder; `api_tree` asks about a symlinked folder's real path (git refuses paths beyond a symlink). Folder stamps (`dir_stamp`) hash names and types only (plus a `.gitignore`'s mtime and, in a work tree, `ignore_rules`: the mtimes of info/exclude and the `.gitignore` files above the folder up to the top), so saving a file doesn't relist its folder but a new ignore rule does. A plain-text walk search runs in the request's thread and checks `client_gone` itself every 0.2 s. Status drops nested repos/worktrees (`dir/` entries) and counts them as `nested`. Searches stop after `SEARCH_TIMEOUT` (504; `MDEDIT_SEARCH_TIMEOUT` shortens it) or when the client disconnects (`Watchdog`, `REQUEST.conn`; search.js aborts a superseded search); a regex search runs in a child process (`search_child`: `python -I -c` importing this module, killed by process group) because Python's re can backtrack for hours holding the GIL. The git engine greps tracked files, then untracked non-ignored ones as literal pathspecs (`--untracked` would drop tracked files that match an ignore rule), skips files over 5 MB, and `grep_records` parses in one pass with lines capped at `LINE_MAX`. The walk reads regular files only (`lstat`: a FIFO would block it for ever). `safe_path` turns a symlink loop into ValueError (3.9-3.12 raise RuntimeError; 3.13 hands back the link). Query strings and `/raw/` paths decode with `surrogateescape`, and the front end encodes paths with `UI.encPath` (and reads `location.hash` with its inverse `UI.decPath`), so non-UTF-8 file names round-trip. `Handler.answer` has a catch-all 500. `/raw/` (agent-controlled files) streams in 64 KiB chunks (never `read_bytes` of a multi-GB file), always sets the sandbox CSP + `X-Content-Type-Options: nosniff`, and adds `Content-Disposition: attachment` (no filename — the agent picks it, could hold CR/LF) for active types (`RAW_ACTIVE`: html/svg/xml/js/pdf and `*+xml`) unless `Sec-Fetch-Dest: image` (the image viewer's `<img>`); tabs.js drops the raw-file link above `RAW_LINK_MAX` (100 MB). PDF export (`export_pdf`, SEC-GIT-002/003): renders the print HTML in a temp dir OUTSIDE ROOT, rewrites `src="/raw/…"` through `safe_path` (`pdf_image_src`; `../` and symlinks can't reach outside ROOT), a meta CSP in `PDF_TEMPLATE` blocks scripts/frames/plugins (only images + CDN styles load), and writes `<name>.pdf` with `os.open(O_NOFOLLOW)` so a planted symlink can't redirect the write. Tests: `tests/test_fs.py`, `test_git.py`, `test_search.py` (both engines), `test_raw.py`, `test_pdf.py`, helpers in `tests/gitutil.py`.
- Every request passes `Handler.guard` first, else 403: Host must be 127.0.0.1, localhost or [::1] (any port, so port forwarding works), and Origin, when present (required on PUT/POST and the WebSocket), must be `http://` + Host — so a `null` Origin (a sandboxed document's fetch) is refused too, on GET as well. `/api/` and `/raw/` also refuse `Sec-Fetch-Site: cross-site`/`same-site` (another site's `<img>` or `<iframe>`). Test clients must send a matching Origin. `Handler.end_headers` adds a site-wide CSP (`APP_CSP`: self + the pinned cdnjs/jsdelivr CDNs, `'unsafe-inline'`/`'unsafe-eval'` and `ws:`, needed by the no-build front end) to every `text/html` response that didn't set its own CSP (so the app page is covered but `/raw/`'s sandbox policy and JSON responses are not).
- Tests: `uv run pytest` (`tests/`, dev group in `pyproject.toml`; CI in `.github/workflows/test.yml` on 3.9 and 3.13). Each test starts real servers (`python -m md_collab_editor --port 0`, see `conftest.py`/`helpers.py`) and fails if any process they started outlives them. The servers' IDE link lock folders are the test's own (`conftest.py` sets `CLAUDE_CONFIG_DIR` and `CLAUDE_SANDBOX_SHARED_CONFIG`; with no `.claude` in the latter, launcher-mode agents such as bash get no link and no extra arguments). Tests that need Linux tools (util-linux `script`, GNU `stat`, `/proc`) are marked `needs_linux` (`helpers.py`) and skip elsewhere. `test_e2e.py` drives the page with Python Playwright (3.10+, needs `uv run playwright install chromium` and CDN access), skipping without a browser unless `MD_EDITOR_E2E=require` (set in CI).
- Front end: no build step; libraries come from CDNs (marked 12, CodeMirror 5 with its merge addon and `diff_match_patch`, DOMPurify, highlight.js, KaTeX, mermaid 10, github-markdown-css, Typo.js, xterm.js 5 with addon-fit and addon-web-links).
- Front-end modules (plain scripts exposing globals, loaded in this order before app.js; each documents its interface at the top): `ui.js` (`UI`: api, store, event bus `root`/`ready`/`theme`, `UI.menu` context menus, `UI.dialog`/`confirm`, `UI.toast`, `UI.statusItem` status-bar slots, `UI.stat` the one shared `POST /api/stat` poll, `UI.sendToTerminal` → `Term.mention`), `activity.js` (`Activity.register(id, {icon, title, panelEl, onShow, onHide})` → handle with `panel`, `setBadge`; Source Control and Search start as empty placeholders), `tabs.js` (`Tabs`: one model per open file = a `CodeMirror.Doc` swapped into app.js's single editor with `swapDoc`; preview/pinned tabs, custom tabs via `Tabs.openCustom` + `Tabs.registerType` for persistence, `Tabs.acquire`/`linkedDoc` for a second editor on a file, events `activate`/`change`/`saved`/`disk-change`/`dispose`…; tabs remembered per root in `mdedit.tabs:<root>`), `explorer.js` (`Explorer`: lazy tree, `decorate` hook), `proposal.js` (`Proposals`, after search.js), then app.js (`cur` = the active file tab's model; `window.App.showTerminal`). Autosave is per category (`mdedit.autosave.md` default on, `.other` off); dirty = `!doc.isClean(cleanGen)`. A model deleted on disk (`markDeleted`, also on a 409 whose version is "0") is never autosaved (`save(m, force, auto)`), and closing it asks; undoing back to clean after a conflict re-checks the disk. `Tabs.renameBlocked` stops Explorer renaming onto an open dirty deleted file; `renamePath` closes clean tabs at the destination. Activity keeps the remembered panel id until it is registered (`shown()`) and calls a re-registered panel's real `onShow` in a microtask. The side bar and Claude panel widths are clamped so the editor keeps 240 px (`maxWidth`, `fitColumns`). CodeMirror modes autoload via `mode/meta` + `addon/mode/loadmode` (simple/multiplex addons are preloaded for the modes that need them).
- `scm.js` (`SCM`, after explorer.js): the Source Control panel polls `/api/git/info` + `/api/git/status?base=head|branch` (2 s while open, 10 s otherwise, and right after saves; base in `mdedit.scm.base`), sets the badge and the `#stat-branch` status item, and shows letters in the Explorer through `Explorer.decorate` (calling `Explorer.render()` only when they change). Diff tabs are `Tabs.openCustom` tabs of kind `diff` (id `scm:<mode>:<path>`, restored through `Tabs.registerType`) that hold the file's model. The side-by-side view is `CodeMirror.MergeView` (`connect: 'align'`, `revertButtons`; `diff_match_patch` must load before `merge.min.js`) with `value: Tabs.linkedDoc(model)`, so its right side shares the file's history and dirty state. It is only built while its tab is on screen (CodeMirror measures what it shows); on show it refreshes and forces the addon's realign (`mv.left.forceUpdate('full')`). Rebuilding one must first `swapDoc` the linked doc out of the old editor. The inline view is a read-only CodeMirror of interleaved rows, rebuilt 300 ms after model changes. Gutter change bars are `addLineClass(line, 'gutter', 'scm-add|scm-mod|scm-del')` on each model's Doc (so they follow `swapDoc`), drawn by CSS on `.CodeMirror-gutter-background` in an 8 px `scm-gutter` column. `lineChunks` (`linediff.js`) uses dmp's `diff_linesToChars_` with `\n` appended to both sides, so chunk lines are CodeMirror lines; it is 16-bit, so over 65,000 distinct lines fall back to one coarse chunk. The gutter's diff runs in `scm-worker.js` (one at a time, skipped when the doc's `changeGeneration()` and the base are unchanged; synchronous fallback if the worker fails); a diff tab caches its chunks by generation (`diffChunks`), skips stats while hidden, and parks a hidden MergeView's editor on an empty Doc (the addon re-diffs on every change and on `swapDoc`). Inline revert arrows and the menu's Revert check that the generation is the one the rows were built from. HEAD text is cached per path until `info.head` changes; a file renamed since HEAD (status R, and no file of its name in HEAD) gets its bars against `old_path`'s HEAD text. Discard uses `Tabs.reload(model)` to drop unsaved edits. Alt/Shift+Alt+F5 is a `document` listener. Tests: `tests/test_e2e_scm.py`.
- `search.js` (`Search`, after explorer.js/scm.js): quick open (Ctrl/Cmd+P, a modal over `/api/allfiles` with its own DP fuzzy matcher; recent files per root in `mdedit.recent:<root>`, fed by Tabs `activate`), the Search panel (`/api/search`, one request in flight, 300 ms debounce; query/options/globs in `mdedit.search`), and Send to Claude terminal for any CodeMirror whose doc is a model's or linked to it (`Search.fileOf`): Ctrl/Cmd+Alt+L and the editor context menu are `document` listeners that skip events already `defaultPrevented` (app.js's extraKeys, the spelling menu, scm.js's diff menus), and Shift+right-click keeps the browser's menu. Ctrl/Cmd+P and Ctrl/Cmd+Shift+F are caught on `window` in the capture phase (CodeMirror binds Shift-Ctrl-F to replace, so replace moves to Ctrl-H in `keyMap.pcDefault`) and skipped in `#term`, dialogs and the folder browser. `UI.sendToTerminal` is async: `Term.mention` shows the panel, waits up to 5 s for a terminal that is still connecting (`Term.running()`: this connection's status says running), and queues a `mention` message in term.js's input queue (`pending`/`flush`, which holds typed text and messages in order), so one sent while the replay is drawn waits behind typed keys; the server works out the `@path#La-b` (relative to the session's folder) and sends it over the IDE link or types it. Chrome logs every 4xx fetch as a console error, so e2e tests that expect a 400 (invalid regex) must drop that entry. Tests: `tests/test_e2e_search.py` (the terminal test runs `bash --norc --noprofile -i` with `HISTFILE=/dev/null`, reads the `mention` messages from the page's WebSocket frames and what the server typed from the screen).
- Gotchas: DOMPurify strips attributes containing `-->` (so mermaid source is kept as element text); mermaid.render is not re-entrant (renders are queued); blur CodeMirror before calling setSelection from preview code, or its input poll re-types the selection and wipes markers. Spell checking is our own (`static/spell.js`: Typo.js plus the `dictionary-en-gb` Hunspell files from jsDelivr, suggestions in `spell-worker.js`), shown by a CodeMirror overlay; code/URL/HTML exclusions are added per line in app.js's `renderLine` handler. A model's Doc must only ever be attached to the main editor (a Doc can't be in two editors): other editors use `Tabs.linkedDoc(model)` (shared history, so one dirty state) and unlink it when done. The tree re-renders only on structure changes (`updateMarks` otherwise), so a click's rows aren't replaced between mousedown and click. Explorer gets a folder's stamp *before* its listing, so a change in between only causes one extra reload. tabs.js's `renderStrip` keeps the tab elements: Chrome only fires dblclick (pin) when both clicks land on the same node. Horizontal padding must go on `pre.CodeMirror-line`, never on `.CodeMirror-lines`, which shifts the per-line gutter elements (line numbers, change bars) off their columns. `location.hash` names the active tab's file (set in `Tabs.activate`; empty for a diff): app.js reads it *before* `Tabs.restore()`, which rewrites it, and opens it afterwards, and opens the command line's file (`conf.initial`) once per browser tab (sessionStorage), so a reload keeps the tab that was on screen. Editing pins the active preview tab only; a preview tab is replaced unless it is the last holder of a dirty model (`losesWork`). In a window ≤ 800 px wide (the CSS breakpoint) the side bar and the Claude panel are overlays, one at a time: `Activity.setSidebar(true)` hides the panel and app.js's `showClaudePanel()` hides the side bar without remembering that. Alt+W (close tab) is a `document` listener that leaves text boxes alone. `e2e` tests for these are in `tests/test_e2e_ide.py`.
